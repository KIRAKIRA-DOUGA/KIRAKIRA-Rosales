# 数据迁移

## 评论点赞和点踩的一次性迁移

`develop` 和 `production` 的发布 PR 都需记录下列步骤和脚本路径。两个环境各执行一次。[迁移脚本](../scripts/migrate-comment-votes.mjs)

1. 暂停评论的发布、删除、点赞和点踩，等待旧实例正在处理的请求完成。备份目标数据库。
2. 从本版本的构建产物或源码目录运行迁移。源码目录先执行 `npm ci` 和 `npm run build`。在部署环境通过密钥设置 `COMMENT_VOTE_MIGRATION_URI`（含目标集群的认证和 TLS 选项）和 `MONGODB_NAME`（业务数据库名），然后执行 `node scripts/migrate-comment-votes.mjs`。
3. 确认脚本输出目标数据库名和迁移完成，再启动新版并恢复评论写入。中断时保持暂停，重新执行同一脚本。完成标记会阻止再次导入已被用户取消的旧记录。

脚本保留两张旧表，只合并指向现存评论和正确视频的有效记录。每个用户在同一评论上保留最后编辑的一条，时间相同时取较大的原记录 ID。随后按新表重建所有评论的赞数和踩数，包括应当归零的评论。切换后的新操作只写新表。恢复写入后如需退回旧版，应先将新状态迁回旧表或选择经确认的恢复点。

评论列表直接读取缓存计数，登录用户另外查询自己的状态。并发增减在各实例内合并写入。数量变动或用户重复操作时，缓存不超过 200 的方向可按记录校准，每个方向最多读取 201 条。同一评论跨实例每 30 秒最多启动一轮，由当前请求触发。用户状态先保存，进程中断或跨实例写入重叠时显示数量可能暂时有偏差。

## 视频点赞和点踩的一次性迁移

在部署包含视频赞踩修复的版本时，分别在 `develop` 和 `production` 的发布 PR 中记录以下步骤。[视频迁移脚本](../scripts/migrate-video-votes.mjs)

1. 暂停视频点赞、点踩和取消操作，等待旧实例完成请求并备份目标数据库。若同时部署评论迁移，一并暂停上节所列的写入。
2. 在新版构建目录设置同一业务库的 `COMMENT_VOTE_MIGRATION_URI` 和 `MONGODB_NAME`，执行 `node scripts/migrate-video-votes.mjs`。两个迁移脚本可以依次执行。
3. 确认脚本输出数据库名和完成状态，再启用新版接口。脚本保留旧表，将每个视频、每名用户的最后一条有效记录合入 `video-votes`。时间相同取较大的记录 ID。中断后可在暂停期间重跑，完成标记防止重新导入已取消的记录。恢复写入后回退须迁回新状态或恢复经确认的备份。
